# Ответы на контрольные вопросы

**Практическая работа по PHP №5:** Стрелочные функции (`fn`) и анонимные функции  
**Дисциплина:** Разработка веб-приложений на PHP

---

## 1. Чем стрелочная функция `fn` отличается от классической анонимной функции `function`?

| Критерий | Классическая анонимная функция (`function () use (...)`) | Стрелочная функция (`fn () => ...`) |
| :--- | :--- | :--- |
| **Тело функции** | Может содержать любое количество инструкций, условий и циклов в `{ ... }` | Содержит строго **одно выражение** |
| **Возврат значения** | Требуется явный оператор `return` | Результат единственного выражения возвращается автоматически |
| **Захват внешних переменных** | Нужно явно перечислять в `use ($a, $b)` | Происходит **автоматически** (указывать `use` не нужно) |
| **Изменение внешних переменных** | Возможно при захвате по ссылке: `use (&$x)` | Невозможно — переменные захватываются только по значению |
| **Типичное применение** | Многострочная логика, сложные обработчики, изменение внешнего состояния | Короткие callback-функции в `array_map`, `array_filter`, `array_reduce`, `usort` |

---

## 2. Как `fn` захватывает переменные из внешней области видимости? Почему изменение переменной после создания функции не влияет на неё?

Стрелочная функция автоматически захватывает все используемые внутри неё переменные из родительской области видимости **по значению** в момент создания функции (по механизму раннего связывания, аналогично `use ($var)` без `&`).

В момент объявления `fn` внутри замыкания сохраняется **копия** текущего значения переменной. Поэтому если изменить внешнюю переменную позже, копия внутри уже созданной стрелочной функции останется прежней, и результат её вызова не изменится.

## 3. Можно ли записать в теле `fn` несколько инструкций? Как обойти это ограничение, если логика сложная?

Нет, синтаксис стрелочной функции в PHP разрешает только **одно выражение** после `=>` — писать блок `{ ... }` с несколькими инструкциями (например, `if`, циклы `foreach`, несколько присваиваний) внутри `fn` нельзя.

**Как обойти ограничение при сложной логике:**
1. Для простых ветвлений использовать **тернарный оператор** (`? :`), оператор объединения с null (`??`) или выражение **`match`** (PHP 8.0+), так как они являются одиночными выражениями.
2. Вынести сложную логику в **отдельную именованную функцию или метод** и вызвать её внутри `fn`: `fn($x) => processItem($x)`.
3. Использовать **классическую анонимную функцию** `function (...) use (...) { ... }`, если многострочную логику удобнее описать прямо на месте.

## 4. Что возвращают `array_map`, `array_filter` и `array_reduce`? Чем отличаются их callback-функции?

| Функция | Что возвращает | Сигнатура и роль callback-функции |
| :--- | :--- | :--- |
| **`array_map($callback, $array)`** | Новый массив **той же длины**, где каждый элемент преобразован callback-функцией | `fn($item) => $newValue` — принимает элемент массива и возвращает новое (преобразованное) значение. *(Callback передаётся первым аргументом.)* |
| **`array_filter($array, $callback)`** | Новый массив, содержащий **только те элементы**, для которых callback вернул `true` (ключи исходного массива сохраняются) | `fn($item): bool => ...` — предикат; принимает элемент и возвращает `bool` (`true` — оставить, `false` — исключить). *(Callback передаётся вторым аргументом.)* |
| **`array_reduce($array, $callback, $initial)`** | **Одно итоговое значение** (число, строка, массив и т.д.), полученное свёрткой всех элементов | `fn($carry, $item) => $newCarry` — принимает аккумулятор (`$carry`) и текущий элемент (`$item`), возвращает обновлённое значение аккумулятора. |

## 5. Как работает оператор `<=>` и почему он удобен в `usort()`?

Оператор `<=>` (spaceship, «космический корабль») выполняет **трёхстороннее сравнение** двух операндов `$a <=> $b` и возвращает целое число:
- `-1`, если `$a < $b`;
- `0`, если `$a == $b`;
- `1`, если `$a > $b`.

Функция `usort($array, $callback)` ожидает от callback-функции сравнения именно такое возвращаемое значение (меньше нуля, ноль или больше нуля), чтобы определить порядок элементов. Вместо громоздкой конструкции с `if / elseif / else` оператор `<=>` позволяет записать сортировку в одну строку:
- по возрастанию: `usort($items, fn($a, $b) => $a['price'] <=> $b['price']);`
- по убыванию: `usort($items, fn($a, $b) => $b['price'] <=> $a['price']);`

## 6. Что выведет код `$f = fn($x) => fn($y) => $x * $y; echo $f(2)(5);`? Объясните.

Код выведет **`10`**.

**Пошаговое объяснение:**
1. `$f` — это стрелочная функция, которая принимает аргумент `$x` и возвращает **новую вложенную стрелочную функцию** `fn($y) => $x * $y`.
2. Вызов `$f(2)` передаёт `$x = 2` и возвращает функцию `fn($y) => 2 * $y`, в которой значение `$x = 2` автоматически захвачено по значению (это пример замыкания / каррирования).
3. Следующие скобки `(5)` сразу вызывают возвращённую функцию с аргументом `$y = 5`: вычисляется `2 * 5`, что даёт `10`.
4. `echo` выводит результат `10`.
