# Ответы на контрольные вопросы

## 1. Чем класс отличается от объекта?
Класс — описание свойств и методов, то есть шаблон. Объект — конкретный экземпляр класса, созданный через `new`. Разные объекты одного класса могут хранить разные значения обычных свойств.

## 2. Для чего нужен конструктор и когда он вызывается?
Метод `__construct()` вызывается автоматически при создании объекта через `new`. Он принимает исходные данные, задаёт начальное состояние и может проверять корректность аргументов. Если наследник определил собственный конструктор, конструктор родителя вызывают явно через `parent::__construct(...)`.

## 3. Что означает $this и почему он недоступен в статических методах?
`$this` обозначает текущий объект. Через `$this->name` читают свойство, через `$this->method()` вызывают метод. Статический метод относится к классу и может вызываться без объекта, поэтому `$this` в нём отсутствует.

## 4. Чем отличается $obj2 = $obj1 от $obj2 = clone $obj1?
При обычном присваивании обе переменные содержат идентификатор одного объекта. Изменение его свойства видно через обе переменные. Это не то же самое, что ссылка между переменными через `&`: присваивание другой сущности одной переменной не переназначает вторую.

`clone` создаёт отдельный объект с копиями значений свойств. По умолчанию копирование поверхностное: если свойство содержит другой объект, вложенный объект автоматически не клонируется. Дополнительное копирование можно описать в `__clone()`.

## 5. Чем статическое свойство отличается от обычного? Как к нему обратиться?
Обычное свойство принадлежит конкретному объекту: `$student->firstName`. Статическое принадлежит классу и общее для его экземпляров: `Student::$totalStudents`. Внутри класса можно использовать `self::$totalStudents`. Статическое свойство не появляется как обычное поле каждого объекта в `get_object_vars()`.

## 6. Что такое readonly-свойство и когда его можно присвоить?
Типизированное `readonly`-свойство запрещает обычное изменение после инициализации. В работе оно инициализируется в конструкторе: `public readonly int $id`. Повторное присваивание приводит к `Error`.

Для PHP 8.1–8.3 первоначальная инициализация разрешена из области класса, объявившего свойство. Начиная с PHP 8.4 по умолчанию доступ к записи — `protected(set)`, поэтому инициализацию может выполнить и наследник. В PHP 8.3+ есть специальное исключение: readonly-свойство можно переинициализировать при клонировании внутри `__clone()`. В этих практических работах эти новые возможности не используются.

`readonly` не делает объект внутри свойства неизменяемым: запрет относится к самому свойству, а не ко всему состоянию вложенного объекта.

## 7. Что такое продвижение свойств в конструкторе?
Сокращённое объявление свойства и его инициализация прямо в параметрах конструктора:

```php
public function __construct(public string $name) {}
```

Это заменяет отдельное объявление `public string $name;` и присваивание `$this->name = $name;` в теле конструктора.

## 8. Как реализовать цепочку вызовов методов?
Каждый метод цепочки возвращает объект, у которого можно вызвать следующий метод. В изменяемом конструкторе запросов методы объявлены с возвращаемым типом `static` и возвращают `$this`:

```php
public function limit(int $count): static
{
    $this->rowLimit = $count;
    return $this;
}
```

Пример: `QueryBuilder::table('users')->where('age', '>=', 18)->limit(10)`.

## 9. Назовите три магических метода и случаи, когда PHP их вызывает
- `__construct()` — при создании объекта.
- `__toString()` — когда объект используется как строка, например в `echo`.
- `__call()` — при вызове недоступного или несуществующего метода объекта.

В работе также используется `__set()`: он перехватывает запись в недоступное или несуществующее свойство. Он не отменяет проверку типов и readonly для доступных объявленных свойств.

## 10. Чем protected отличается от private при наследовании?
`protected` разрешает доступ из объявившего класса и его наследников. `private` доступен только в области класса, где он объявлен. Поэтому `Manager` может прочитать `$this->baseSalary`, но не может напрямую прочитать закрытый паспорт `Employee`.

## 11. Что делает ключевое слово final?
`final class` запрещает наследование от класса. `final` у метода запрещает переопределять этот метод в наследниках. В работе `final public function getMaskedPassport()` не позволяет заменить маскировку паспорта в `Developer`.

## 12. Как работает spl_autoload_register?
Функция регистрирует обработчик автозагрузки. Когда PHP нужен ещё не определённый класс, он передаёт обработчикам его полное имя. Обработчик проверяет префикс, преобразует оставшуюся часть имени в путь и подключает файл. Уже загруженный класс повторно загружать не требуется. Оператор `use` сам по себе файл класса не подключает.

## 13. Как стандарт PSR-4 связывает пространство имён и путь к файлу?
Префикс пространства имён сопоставляется базовому каталогу. При `"Shop\\": "src/"` класс `Shop\Models\Product` находится в `src/Models/Product.php`. Префикс убирается, оставшиеся разделители `\` заменяются разделителями каталогов, добавляется `.php`. Регистр имён каталогов и файлов должен соответствовать регистру имён в пространстве имён и классе; это особенно важно при переносе проекта с Windows на Linux.

## 14. Когда нужно выполнять composer dump-autoload?
После добавления или изменения настроек автозагрузки в `composer.json`, например префикса или базового каталога. Команда создаёт или обновляет сгенерированные файлы автозагрузчика в `vendor/`.

При обычном PSR-4 добавление файла класса или подпапки внутри уже сопоставленного каталога само по себе не требует повторного запуска команды. Для `classmap` и авторитетной карты классов после добавления классов карту нужно обновлять. После клонирования нашего репозитория, где `vendor/` не хранится, достаточно перейти в `pr2` и выполнить `composer dump-autoload`.
