# Ответы на контрольные вопросы

**Практическая работа по PHP:** Основы — автозагрузка классов, абстрактные классы и свойства  
**Дисциплина:** Разработка веб-приложений на PHP

---

## 1. Какой момент времени выбирает PHP для вызова автозагрузчика и что произойдёт, если файл класса так и не найден?

PHP обращается к механизму автозагрузки **лениво** — в момент первого обращения к ещё не объявленному классу, интерфейсу, трейту или перечислению (например, при создании объекта через `new`, наследовании через `extends`, реализации `implements`, вызове статического метода или обращении к константе класса).

Когда интерпретатор встречает неизвестное имя класса, он не завершает работу с ошибкой сразу, а последовательно вызывает все функции-автозагрузчики, зарегистрированные через `spl_autoload_register()`, передавая им полное имя класса (включая пространство имён). Если после прохождения всей очереди автозагрузчиков класс так и не был загружен, PHP генерирует фатальную ошибку:

```text
Fatal error: Uncaught Error: Class "App\Models\UnknownClass" not found
```

## 2. В чём преимущество `spl_autoload_register()` перед удалённой функцией `__autoload()`?

1. **Поддержка нескольких автозагрузчиков.** Функцию `__autoload()` можно было объявить в проекте только один раз, из-за чего подключение сторонних библиотек со своими автозагрузчиками приводило к конфликту имён. `spl_autoload_register()` позволяет зарегистрировать целую очередь независимых функций-автозагрузчиков, которые вызываются по порядку до тех пор, пока класс не будет найден.
2. **Гибкость управления.** Можно добавлять автозагрузчики в начало или конец очереди (`$prepend = true`), а также удалять их с помощью `spl_autoload_unregister()`.
3. **Совместимость с современным PHP.** Функция `__autoload()` была объявлена устаревшей в PHP 7.2 и полностью удалена в PHP 8.0, поэтому в современных версиях языка использовать её невозможно.

## 3. Чем абстрактный класс отличается от интерфейса? Когда что выбрать?

| Критерий | Абстрактный класс (`abstract class`) | Интерфейс (`interface`) |
| :--- | :--- | :--- |
| **Назначение** | Описывает базовую сущность и общее поведение («является чем-то») | Описывает контракт / набор возможностей («умеет делать что-то») |
| **Реализация методов** | Может содержать как абстрактные методы (без тела), так и обычные методы с готовой реализацией | Содержит только сигнатуры методов без реализации |
| **Свойства (состояние)** | Может хранить обычные, статические, `readonly`-свойства и конструктор | Не может содержать обычные свойства (только константы) |
| **Множественное наследование** | Класс может унаследовать только **один** абстрактный класс (`extends`) | Класс может реализовать **сколько угодно** интерфейсов (`implements`) |
| **Модификаторы доступа** | Методы и свойства могут быть `public`, `protected`, `private` (абстрактные методы — `public` или `protected`) | Все методы интерфейса всегда `public` |

**Когда что выбрать:**
- **Абстрактный класс** выбирают для семейства тесно связанных сущностей, у которых есть общее состояние (свойства) и повторяющийся код (например, `Shape` → `Circle`, `Rectangle`, `Triangle` или `Employee` → `Manager`, `Developer`).
- **Интерфейс** выбирают, когда нужно задать единый контракт для разных, не связанных общим предком классов (например, `JsonSerializable`, `Countable`, `LoggerInterface`) или когда классу нужно совмещать несколько независимых ролей.

## 4. Можно ли создать объект абстрактного класса? Можно ли объявить абстрактное свойство?

- **Создать объект абстрактного класса нельзя.** Попытка выполнить `new Shape()` приведёт к фатальной ошибке `Error: Cannot instantiate abstract class Shape`. Абстрактный класс предназначен исключительно для наследования — создавать экземпляры можно только от конкретных классов-наследников, реализовавших все абстрактные методы.
- **Объявить абстрактное свойство в классическом смысле нельзя** (в базовом ООП PHP ключевое слово `abstract` применимо к классам и методам). Чтобы обязать классы-наследники предоставлять определённые данные, используют:
  - конструктор абстрактного класса с нужными `protected`-свойствами (как в `Employee` и `Product`);
  - абстрактные геттеры (например, `abstract protected function getName(): string;`).

## 5. Чем `static`-свойство отличается от обычного? Как обратиться к нему внутри и вне класса?

- **Обычное свойство** принадлежит конкретному экземпляру (объекту) класса: у каждого объекта хранится своя независимая копия значения, обращение идёт через `$this->property` внутри класса и `$object->property` снаружи.
- **Статическое свойство (`static`)** принадлежит самому классу, а не отдельному объекту — оно одно и является общим для всех созданных экземпляров (например, счётчик созданных объектов `$count`).

**Способы обращения:**
- **Внутри класса:** `self::$count` (ссылка на текущий класс, где написан код) или `static::$count` (позднее статическое связывание — учитывает класс-наследник).
- **Вне класса:** `ИмяКласса::$count` (если свойство объявлено как `public`; если оно `private` или `protected`, доступ снаружи организуют через публичный статический метод, например `Product::getCount()`).

## 6. Что делает модификатор `readonly` и какие ограничения он накладывает?

Модификатор `readonly` (добавлен в PHP 8.1) запрещает изменять значение свойства после его первой инициализации — обычно значение задаётся один раз в конструкторе, а далее свойство доступно только для чтения.

**Основные ограничения:**
1. **Обязательная типизация.** У `readonly`-свойства обязательно должен быть указан тип (например, `public readonly string $title;`).
2. **Нельзя задавать значение по умолчанию** при объявлении свойства (иначе оно считалось бы уже инициализированным и фактически превратилось бы в константу).
3. **Нельзя объявлять как `static`.** Модификатор `readonly` применим только к свойствам экземпляра.
4. **Инициализация только в области видимости объявляющего класса.** Присвоить значение `readonly`-свойству впервые можно только изнутри того класса, в котором оно объявлено (присвоить его снаружи или из наследника нельзя).
5. **Запрет повторного изменения и удаления.** Повторное присваивание значения, инкремент/декремент или вызов `unset()` для уже инициализированного `readonly`-свойства вызовет фатальную ошибку `Error`.
